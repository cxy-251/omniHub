# 桌面端手机迁移与部署

入口：**设置 → 手机与迁移**。只有本机桌面端管理员可以操作，Web 不提供此入口。

## 连接与普通漫画

1. 插 USB 数据线，在手机允许 USB 调试，点击「刷新设备」。同一手机同时有无线和有线连接时优先使用 USB。
2. 选择本机来源库，确认手机资源库目录（必须已经在手机 omniHub 中创建，包含 `omnilibrary.json`）。默认从现有手机短视频路径推导。
3. 选择全部普通漫画，或展开列表搜索、勾选部分漫画；设置手机预留空间。
4. 「检查迁移内容与空间」生成计划，再点「开始 / 继续复制到手机」。默认保留本机文件；只有主动勾选迁移选项才会在手机副本完整校验后回收本机副本。

范围是 `media_library/manga/standard/` 中的 CBZ，保留相对目录；不迁移成人漫画、账号数据库、阅读历史或缓存。手机漫画页面刷新后会从资源库目录发现新文件。

- 漫画预检、启动、续传及后续每次 ADB 操作都检查 USB 传输通道；同一手机的无线 ADB 不替代有线。换手机拒绝续传。
- 小块流式传输，手机隐藏临时目录保留文件内断点；继续时验证已传前缀，完整文件校验通过才发布。不会把半本书放进可浏览目录，不覆盖同名不同内容的文件。
- 切换页面不停止任务；任务由服务端执行。暂停、断线或服务端退出后保留迁移计划，重新启动后可继续。再次预检相同选择会保留原断点。
- 本机副本通过系统回收站回收，失败会明确提示并保留任务记录，没有永久删除降级。
- 进度在操作区上方；过程日志可展开，最多保留 120 条。大文件传输按 8 MiB 分块，不整体读入内存。

## 从 Deck 更新或首次部署手机服务端

**无线 ADB 足够，不要求 USB。** 在 Deck 桌面端选择手机，点击「检查设备 / 版本」，确认本机项目目录后点击「构建本机代码并更新手机服务端」。

- 构建来源是 Deck 上选择的 omniHub 源码目录，包含未提交的代码。正常会自动找到当前项目，可手动选择其他 checkout。
- Deck 先用 pnpm 构建 Web，再用 Go 构建手机 Termux 所需的 arm64 服务端；Web 内嵌在同一个服务端可执行文件中。构建命令低优先级运行，Go 使用 `-p 2`；本机需有 Go、pnpm、Node。缺少 Web 依赖时按锁文件安装。
- 直接传送构建出的 `omnihub-server` 和启动脚本到手机，通过版本执行检查、文件 SHA-256 校验、启动与健康检查完成切换。手机只运行服务端，客户端用浏览器；不需要 APK、GitHub 发布或 Actions 安装包。
- 手机需要 Termux、OpenSSH、curl，`sshd` 正在运行且已授权 Deck 公钥。连接设置可选择私钥、SSH 用户/端口、安装目录和服务端口；用户名可以自动识别。准备命令只包含公钥，私钥不上传。
- ADB 为选中的设备建立临时 SSH 转发，不用手填 Wi-Fi IP；任务结束释放转发。首次安装 Termux、允许其访问存储仍在手机完成。
- 只更新服务端和启动脚本；账号、配置、资源库保持原样。旧程序保存在 `.previous/`，新程序启动失败尝试回退。程序回退不代表数据库格式可逆向降级。
- 过程日志包括本机构建和手机切换。取消构建会同时停止其子进程。手机切换阶段独立执行，连接丢失后仍会完成或回退，应先重新检查设备，避免重复部署。
- 首次部署需填写管理员名称和密码；密码不保存到设置和日志。若管理员创建阶段被中断，可在手机执行安装目录下的 `omnihub-server --setup-admin 用户名`。
- 构建产物保存在本次任务临时目录，任务结束清除。手机安装日志保留于 `.deploy-时间戳/deploy.log`，成功后清掉上传的临时程序。

## 验证记录（2026-11-05）

- Go 关键边界测试：部分字节写入后续传、同名冲突、来源变化、空间不足、符号链接、损坏断点、保存计划失败时不回收、回收后的断点恢复；构建取消后不残留子进程、项目及程序格式校验；更新失败/健康检查失败恢复旧程序；Web、LAN、代理不能操作设备。
- 实际 Qt 客户端 + 隔离服务 + 模拟 ADB/SSH：无线时禁用漫画操作而允许更新；USB 复制测试书并逐字节核对；切换页面后任务继续，返回显示完成；HTTP 绕过 UI 仍拒绝无线传漫画。
- 本轮实际 Qt 按钮触发本机 Web/Go 构建、模拟无线 ADB 上传与哈希校验，隔离模拟手机切换结果；旧程序回退另由 shell 测试覆盖。
- 真实手机只读检查通过：无线 ADB、Termux SSH、安装路径、版本与运行状态可读取。没有传输真实漫画或替换手机程序；本次未验证真实 USB 吞吐量，也未实际更新手机。
- 本机实际 Web + Termux 服务端构建通过，产物确认为 Android arm64 ELF，内嵌 Web；Linux Go 与 Qt 构建通过。整套 server 测试另有既有 `TestMusicChoicesAndRecycleBoundaries` 的系统回收站断言失败；设备相关定向测试通过，未将整套测试标为通过。
