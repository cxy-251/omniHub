# Web 工作台重构

## 范围与定位

Web 是任意浏览器中的工作台，与 Qt 桌面共用 Go、账号和资源库；下载入口仍只在桌面端。本阶段交付导航、设置中心、错误恢复与按需加载，不宣称所有媒体页面已经完成重做。Qt 的视觉及媒体行为不在本轮修改范围内。

视觉基准：深色媒体工作台，224px 宽屏侧栏、中等宽度图标栏、窄屏展开导航。背景 #101318、面板 #191e26、文本 #edf2f7、次要文字 #9aa6b5、强调色 #89d9bc。控件与文字使用原生 DOM；不引入常驻 WebGL、装饰视频、在线字体或全屏模糊。

设计概念及实际效果保存在本机忽略目录 `build/previews/web-ui/`，不进入发布包。

## 已实现

- `WorkbenchNav` 承担浏览器导航，权限仍由 `/api/sections` 决定。设置子路径支持直接打开、刷新和前进后退。
- `SessionSettings` 单独读取和保存登录保持天数。账号设置分成会话、访问权限、用户管理、信任设备，各自读取需要的数据。空设备列表统一为数组，兼容旧服务的 null。
- `PageBoundary` 将页面错误与导航、音频隔离；设置子页有自己的边界。`lazyPage` 在模块加载失败时验证当前 HTML 入口：只有入口确实改变、且没有正在播放的媒体或带脏标记的表单时，才为同一新版本自动刷新一次。其他情况展示恢复操作，避免黑屏和刷新循环。
- Go 的 HTML 入口使用 `Cache-Control: no-cache`，存在的指纹静态文件仍长期缓存，缺失文件使用 `no-store`。
- 漫画书架只引入轻量打开状态；真正打开书籍才载入阅读器。跨页阅读、刷新恢复仍保留，关闭后卸载阅读器实例。
- 短视频管理、相册导入进度和外网连接状态使用串行、可取消的可见页轮询。隐藏浏览器页签时停止请求，回来立即刷新。后台任务不随页面卸载停止。
- 本轮未新增 npm 依赖，也没有增加运行时 Node 服务。

## 诊断与验证

新打开浏览器进入设置未出现原始问题。通过使设置 chunk 不可用，复现了原版本整页空白及 `Failed to fetch dynamically imported module`。这确认了可导致同样症状的失败路径，无法据此断言用户每次黑屏都是同一个触发条件。

本机现有 Chrome 无头模式 + CDP，隔离配置和测试库。没有安装浏览器或 Playwright。验证覆盖：

- 会话天数保存、刷新保留、1–365 范围检查；不修改实际账号策略。
- 设置全部子页、空设备、前进后退、主导航、窄屏展开导航。
- 设置 chunk 失败时其他页可用；恢复按钮可重新进入；确认入口变更后恰好自动刷新一次；注入组件异常后设置子导航仍可恢复。
- 隐藏页签时轮询请求停止，重新激活后立即请求。
- 1505×1045、1280×800、768×1024、390×844；无横向页面溢出。普通流程没有未捕获异常。
- 冷开设置页只请求 auth/status、sections、admin/sessions；没有请求漫画阅读器、AdminPage、Mermaid 或 KaTeX。
- 测试库下冷开设置强制 GC 后 JS 堆约 1.55 MiB；预热其他页面后，40 次设置子页切换前后约 2.24→2.33 MiB。DOM 节点均为 374、监听器均为 199。这是一次局部回归检查，不代表整个浏览器进程、GPU 资源或所有媒体库的内存上限。
- 漫画实际打开、跨页保留、刷新恢复、关闭卸载及页面宽度复位通过。
- TypeScript、Vite、Go 构建及会话鉴权/续期测试通过。
- 2026-11-04 已启动主机新版服务，实际设置页无控制台错误；HTML 200/no-cache、缺失模块 404/no-store 已验证。用户的登录策略仍为原有 30 天。

视觉对照检查：导航顺序与选中态、标题及表单文字、深色/薄荷色配色、主面板与分隔线、字号和间距、窄屏堆叠。保留的差异：实际账户/天数来自服务端，控件按真实浏览器字体排版；概念图中的光泽和纹理不进入运行界面，使用纯色减少合成；账号区不添加装饰图标。概念不是一张覆盖在页面上的图片。

## 仓库借鉴与后续顺序

### 导航与设置精简（2026-11-04）

小说分类和漫画标签改用 `ChannelBar` 的展开式搜索，原有分类/标签选择参数不变；漫画同标签再点取消。设置主导航、账号子导航及音声标签允许换行。设置去除大标题/介绍，登录页仅保留天数表单、反馈与一条规则说明；删除重复的安全说明卡和信任设备跳转区。资源库、短视频、相册、工具的重复页名删除；长配置说明改为原生 details，错误、进度和会话/文件/权限影响仍有明确反馈。

隔离 Chrome + CDP 验证登录天数保存后刷新、非法范围禁用、设置四个账号子页、600 个模拟小说分类中的中文搜索/选择、模拟漫画标签过滤/取消及展开帮助。1280/900/390/320 宽检查通过；320 宽另外检查资源库、短视频、相册、网络设置和工具入口，没有页面横向溢出或运行时异常。截图在 `build/previews/web-compact/`。文档正文中宽代码、表格、公式和图表的内容滚动不属于导航控件，本轮未改变其排版。

### 筛选区域收纳（2026-11-04）

参考本机 omniDeck `web/features/shortvideo/shortvideo.js` 的 `renderShortVideoFolderBar`：常用频道保留在外面，更多作者默认收起，展开后搜索和纵向滚动，选作者不自动收起。omniHub 短视频与图库共用 `ChannelBar`，展开使用内容区全宽，手机自动换为单列，当前频道在收起后仍显示。常用固定项最多六个，其余仍在面板；长列表使用虚拟网格，关闭后卸载，不把整个作者库常驻 DOM。短视频面板可直接固定博主。

音声页移除「音声」大标题及说明，只保留可操作的三个标签；短视频和图库移除没有动作的「浏览」按钮。没有新增依赖或后端接口。

验证使用现有 Chrome + CDP（本会话无 Browser 插件）、隔离 HTTP 模拟数据。5000 分组仅挂载 32 项，实际派发滚轮事件验证纵向滚动；中文搜索、空搜索结果、选择对应 API 参数、固定反馈、Esc 焦点返回、展开/收起及音声顶部通过。1280×800、900×420、390×844 无横向溢出、无运行时错误。截图在忽略目录 `build/previews/web-channels/`；这是交互与布局验证，不是实际媒体数据压力测试。参考中作者按钮换行，这里大列表改为有界网格，保留同样的收纳和连续选择行为。

### 第二阶段：音声与导航空间（2026-11-04）

- 按用户要求取消「omniHub / 页面 / admin / 修改密码 / 退出」顶栏，账号操作迁入侧栏底部或窄屏导航。短窗口的导航区独立滚动，底部音频条通过 ResizeObserver 报告实际高度，避免遮住最后的设置入口。
- 侧栏支持手动收起和左侧边缘恢复，状态保存在本浏览器。修复多联放映固定从窗口左边开始而被导航覆盖的问题：展开时预留侧栏宽度，收起时完整使用窗口；全屏不预留外围边距。1280 宽实测矩阵从左侧 224px 切为 0px，已有合成视频元素保持不变且播放时间继续前进；刷新记忆、900 宽图标栏、390 宽导航和全屏切换通过。测试没有播放真实用户视频。
- 音声提供音乐库、专辑、正在收听三个按需加载页面，路径可直接打开。专辑只请求当前歌手详情；曲目每页 60 首、最多缓存 4 页。歌手列表、专辑网格和曲目列表均虚拟化。音乐库的近期播放刷新与目录刷新分离，切歌不重扫目录。
- 正在收听复用唯一音频引擎，封面使用真实媒体元数据；无封面显示中性图标。支持同步歌词点击定位、手动浏览与恢复跟随、纯文本/无歌词/读取失败反馈。同步歌词以二分定位当前行，仅挂载可见行和少量缓冲行。退出页面取消请求并释放观察器。
- 全局音频条在正在收听页隐藏，其他页保留播放、进度与更多选项。原有点赞、不喜欢、音乐分组及回收功能继续保留。
- 现有 Chrome + CDP、隔离服务和合成音频验证专辑播放、同一 audio 元素跨页继续、歌词跳转、暂停/切歌、纯文本/无歌词、评价切换和账户入口；正常流程无控制台异常。1280×440 的设置按钮可实际点击且位于播放器上方；390、760、900 宽没有页面横向溢出。
- 注入 1500 行同步歌词时只渲染 11 行；手动浏览后恢复跟随、专辑详情刷新、退出与登录入口验证通过。
- 概念与实测截图留在本机 `build/previews/web-music/`。对照了文字层级、封面/歌词两栏、薄荷色当前行、控制区和窄屏堆叠。实际移除概念图顶栏，沿用已有导航选中态；测试音频没有封面，不把概念中的虚构图片当作用户封面。
- 没有新增 npm 包、Go 接口或运行时服务。本阶段没有测定整机 RSS 或真实超大音乐库峰值，不能将虚拟化等同于已完成整个应用的内存优化。

## 性能预算与测量口径

下面是下一阶段的工程门槛建议，不是已全面达成的内存承诺：

- 基础设置入口 JS gzip 控制在 100 KiB 内；当前主 chunk 约 78 KiB，设置子页各约 1–2 KiB。大型渲染器不能进入基础依赖。
- 长列表保持虚拟化和有界分页；缩略图、图片解码、PDF Canvas、3D 纹理需要分别设数量/像素预算。模块代码访问后可能留在 JS 引擎中，卸载组件不等于卸载全部代码。
- 客户端测浏览器 JS 堆、DOM/监听器、浏览器进程 RSS、GPU/解码资源；Qt 单独测 RSS/显存，不能用 Web 的堆代替。
- 服务端测空闲/扫描/播放/导出分别的 RSS 和 Go heap；传输继续流式，重任务通过有限并发子进程释放内存。暂未给服务端或 Qt 新增全局硬内存上限，以免误杀正在运行的功能。
- 固定数据集和设备对比冷启动、预热和往返切页；发布包大小、下载字节、运行时内存分别记录。本轮没有做整站媒体压力测试，不能用设置页结果推断多联放映或超大库的峰值。

技术参考：[Vite 部署后的动态模块加载错误](https://vite.dev/guide/build#load-error-handling)、[React 错误边界](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)。
